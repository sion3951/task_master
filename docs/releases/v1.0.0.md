# task_master v1.0.0

The first release of task_master: a native system monitor for local and
SSH-connected Linux, Windows and macOS machines, written in Odin with a
Vulkan-rendered interface.

## Features

- Overview, CPU, GPU and Mem+Disk dashboards with recent history graphs.
- CPU, RAM, swap, disk, network and supported NVIDIA GPU telemetry.
- Grouped process tables with sorting, pinning, PID expansion and termination.
- SSH host discovery and automatic deployment of bundled remote collectors.
- Optional per-user background persistence that retains recent samples while
  the desktop window is closed.
- Graph inspection, pause controls, display scaling and Linux X11/Wayland support.

## Downloads

Choose the installer matching your operating system and architecture:

- **Linux x64 or ARM64:** `.AppImage` or `.deb`. Release builds target Ubuntu
  22.04 / glibc 2.35 or newer. The host must provide a working Vulkan driver.
- **Windows 11 or newer:** `windows-x64-setup.exe`; Windows 11 ARM64 runs it
  through x64 emulation.
- **macOS 13 or newer:** `amd64.pkg` for Intel or `arm64.pkg` for Apple Silicon.
  MoltenVK is bundled for GPU rendering through Metal.

`SHA256SUMS` contains the SHA-256 checksums of the installer files. GitHub also
provides source archives; these require the build tools documented in the README.

Installers are attached after the Installers workflow completes successfully.
Installation configures platform sensor access; background persistence remains
off until enabled in the app.

## Current limitations

- Non-NVIDIA GPU telemetry is not implemented. Unsupported sensors show an
  unavailable state.
- Summary graphs display the first NVIDIA device. Collection is bounded to
  eight GPUs, 256 logical CPU cores, 16,384 system PIDs and 2,048 GPU PIDs.
- Windows GPU readings depend on NVML and WDDM counter availability; CPU
  hardware sensor access uses the installed sensor service.
- macOS packages use ad-hoc signing by default and are not notarized.
- Remote monitoring requires SSH access and the target machine's supported
  telemetry APIs/drivers. Linux persistence requires a systemd user manager.

See the README for installation, controls, remote setup and diagnostics.
