# task_master v1.0.8

- Stop the background Persistence service from rewriting every machine's full five-minute history to disk each second. With three machines, steady-state disk writes drop from about 12 MB/s (roughly 1 TB/day) to a few KB/s, and service CPU use drops by about 90%.
- On Linux, frequently replaced Persistence files now live in the private runtime directory (`$XDG_RUNTIME_DIR`). A durable copy in the user cache directory is refreshed every 10 minutes and on shutdown, so graphs and I/O totals still survive reboots. Existing v1.0.7 caches are picked up on upgrade.
- Write per-sample live files only while a task_master window is open; opening a window requests the complete recent history immediately.
- Cache writes no longer force a disk sync. Atomic replacement still guarantees readers never see a partial file.
- Failed cache writes, for example on a full disk, back off up to 32 seconds and are reported once instead of every second.
- Background publisher, reader and service threads sleep until there is work instead of polling every 10–100 ms, reducing idle wakeups in the app and the service.
- Keep the Persistence service running when its cache directory cannot be written, instead of exiting without being restarted.

The release workflow builds Linux AppImage and Debian packages, Windows setup executables, macOS installer packages, remote collectors, and signed update metadata for x64 and ARM64.
